# Example domain

Throughout this tutorial series, the example domain is **`ekcloud.dk`**. Wherever you see `ekcloud.dk` — in commands, screenshots, or the committed config files — substitute the domain you registered in [tutorial 01](./01._registering_domains_with_one.com.md).

In this tutorial specifically, replace `<yourdomain>` in the `dig` commands and the A record values with your domain. The actual file edits (in [tls/nginx.conf](../tls/nginx.conf) and [tls/compose.yaml](../tls/compose.yaml)) are itemised in [tutorial 03](./03._running_it_on_the_server.md).

---

# Prerequisite: Have a server

If you don't already have a server running or if you would like to try this setup then create a server.

Make sure that you have a public IP.

Make sure that ports `80` and `443` are open inbound.

If you provisioned with the Terraform in [infrastructure/](../infrastructure/), the NSG in [network.tf](../infrastructure/network.tf) opens both. If you added `443` after the initial apply, re-run:

```bash
$ cd infrastructure
$ terraform apply
```

If your distro also has a host firewall enabled (e.g. `ufw` on Ubuntu), open the ports there too:

```bash
$ sudo ufw allow 80
$ sudo ufw allow 443
```

# Add the A records

Add an A record for the apex domain pointing to the public IP of your server.

| Type | Hostname / Subdomain | Value (IP)       | TTL     |
|------|----------------------|------------------|---------|
| A    | `@` (apex)           | `<your-server-ip>` | default |
| A    | `www`                | `<your-server-ip>` | default |

The `www` record is optional but recommended. If you skip it, leave `www.<yourdomain>` out of the certbot command in the next tutorial.

# Verify the A records

Run the commands below from your local machine. Replace `<yourdomain>` with your full domain, including the TLD (e.g. `ekcloud.dk`).

## 1. Check one.com's nameserver

This asks one.com directly, so it works as soon as the records are saved:

```bash
$ dig @ns01.one.com A <yourdomain> +short
$ dig @ns01.one.com A www.<yourdomain> +short
```

Both should return your server's IP. If not, recheck the records in the one.com DNS settings.

## 2. Check public DNS

**`.dk` domains only:** newly registered `.dk` domains must be verified with MitID before they appear in public DNS. Look for an email from **Punktum dk** and complete the verification first.

```bash
$ dig A <yourdomain> +short
$ dig A www.<yourdomain> +short
```

Both should return your server's IP before you continue to the next tutorial. If they come back empty, the records haven't propagated yet. This usually takes a few minutes but can take longer, so wait and try again.
